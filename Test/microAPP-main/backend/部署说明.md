# 部署指南 (Deployment Guide)

本项目采用 **Docker (Nginx) + PM2 (Node.js)** 架构部署：
- **Docker 容器 (Nginx)**：托管前端静态文件，反向代理 API 请求
- **PM2 (Node.js)**：运行后端服务，监听 8090 端口

## 1. 项目结构

```
DKZHFW-PLATFORM/
├── backend/                 # 后端服务
│   ├── index.js             # 服务入口
│   ├── storage.js           # 数据存储层
│   ├── platformAuth.js      # SSO 认证
│   ├── public/              # 静态资源 & 前端构建文件
│   │   ├── assets/          # 前端 JS/CSS (构建产物)
│   │   ├── icons/           # 图标资源
│   │   ├── images/          # 图片资源
│   │   ├── video/           # 视频资源
│   │   ├── uploads/         # 用户上传文件 (运行时数据)
│   │   └── index.html       # 前端入口
│   ├── db/                  # 数据库相关
│   └── *.json               # 业务数据文件 (运行时数据，不纳入 git)
│
├── frontend/                # 前端源码
│   └── h5/                  # Vue3 + Vite 项目
│
├── sql/                     # 数据库脚本
└── docs/                    # 项目文档
```

### 运行时数据文件 (已加入 .gitignore)

以下文件在服务器运行时会被修改，**不纳入 git 版本管理**，更新代码时不会被覆盖：

- `backend/users.json` — 用户数据
- `backend/data.json` — 订单/申请数据
- `backend/cases.json` — 案例数据
- `backend/services_config.json` — 服务配置数据 (含首页配置)
- `backend/study_showcase.json` — 研学展示数据
- `backend/public/uploads/` — 用户上传的文件

## 4. 首次部署

### 第一步：构建前端

```bash
cd frontend/h5
npm install
npm run build
```

构建完成后，将 `frontend/h5/dist/` 目录内容复制到 `backend/public/`：

```bash
# 清除旧的 assets（保留 uploads、icons 等）
rm -rf backend/public/assets
cp -r frontend/h5/dist/* backend/public/
```

### 第二步：上传代码到服务器

```bash
git add -A
git commit -m "build: 更新前端构建文件"
git push origin main
```

服务器上拉取：

```bash
cd /data/low-altitude
git pull origin main
```

### 第三步：安装后端依赖

```bash
cd /data/low-altitude/backend
npm install --production
```

### 第四步：启动后端服务 (PM2)

```bash
cd /data/low-altitude/backend

# 如果有旧服务先删除
pm2 delete low-altitude-server

# 启动新服务
PORT=8090 pm2 start index.js --name "low-altitude-server"

# 保存进程列表（开机自启）
pm2 save

# 检查是否成功启动
pm2 list
```

### 第五步：部署前端到 Docker Nginx

```bash
# 清除容器内旧的 assets
docker exec lacomnginx1 rm -rf /usr/share/nginx/html/assets

# 复制前端构建文件到容器
docker cp /data/low-altitude/backend/public/index.html lacomnginx1:/usr/share/nginx/html/index.html
docker cp /data/low-altitude/backend/public/assets lacomnginx1:/usr/share/nginx/html/assets
docker cp /data/low-altitude/backend/public/icons lacomnginx1:/usr/share/nginx/html/icons
docker cp /data/low-altitude/backend/public/images lacomnginx1:/usr/share/nginx/html/images
docker cp /data/low-altitude/backend/public/video lacomnginx1:/usr/share/nginx/html/video
docker cp /data/low-altitude/backend/public/override.css lacomnginx1:/usr/share/nginx/html/override.css

# 重载 Nginx
docker exec lacomnginx1 nginx -s reload
```

## 5. 日常更新流程 (重要)

本地修改代码后，按以下步骤同步到生产服务器：

### 步骤一：本地构建前端

```bash
cd frontend/h5
npm run build
```

将构建产物复制到 backend/public/：

```bash
# Windows PowerShell
Remove-Item backend\public\assets -Recurse -Force
Copy-Item -Path frontend\h5\dist\* -Destination backend\public\ -Recurse -Force
```

### 步骤二：提交并推送到 Git

```bash
git add -A
git commit -m "update: 更新描述"
git push origin main
```

### 步骤三：服务器拉取代码

```bash
cd /data/low-altitude
git pull origin main
```

> **注意**：运行时数据文件 (users.json, data.json 等) 已在 .gitignore 中，
> git pull 不会覆盖服务器上的业务数据。

### 步骤四：重启后端服务

```bash
pm2 restart low-altitude-server
```

### 步骤五：更新 Docker 容器内的前端文件

```bash
# 清除旧 assets 并复制新文件
docker exec lacomnginx1 rm -rf /usr/share/nginx/html/assets
docker cp /data/low-altitude/backend/public/index.html lacomnginx1:/usr/share/nginx/html/index.html
docker cp /data/low-altitude/backend/public/assets lacomnginx1:/usr/share/nginx/html/assets
docker cp /data/low-altitude/backend/public/icons lacomnginx1:/usr/share/nginx/html/icons
docker cp /data/low-altitude/backend/public/images lacomnginx1:/usr/share/nginx/html/images
docker cp /data/low-altitude/backend/public/video lacomnginx1:/usr/share/nginx/html/video
docker cp /data/low-altitude/backend/public/override.css lacomnginx1:/usr/share/nginx/html/override.css

# 重载 Nginx
docker exec lacomnginx1 nginx -s reload
```

### 步骤六：验证更新

```bash
# 验证容器内 JS 文件已更新（对比 index.html 引用的文件名）
grep "script" /data/low-altitude/backend/public/index.html
docker exec lacomnginx1 ls /usr/share/nginx/html/assets/ | head -5

# 验证后端服务正常
curl -s http://localhost:8090/api/services/config | head -50
```

浏览器使用 `Ctrl+Shift+R` 强制刷新页面确认更新。

### 快速更新命令汇总

如果只改了后端代码（不涉及前端）：

```bash
cd /data/low-altitude && git pull origin main && pm2 restart low-altitude-server
```

如果前后端都改了（完整更新）：

```bash
cd /data/low-altitude && git pull origin main && pm2 restart low-altitude-server && \
docker exec lacomnginx1 rm -rf /usr/share/nginx/html/assets && \
docker cp /data/low-altitude/backend/public/index.html lacomnginx1:/usr/share/nginx/html/index.html && \
docker cp /data/low-altitude/backend/public/assets lacomnginx1:/usr/share/nginx/html/assets && \
docker cp /data/low-altitude/backend/public/icons lacomnginx1:/usr/share/nginx/html/icons && \
docker cp /data/low-altitude/backend/public/images lacomnginx1:/usr/share/nginx/html/images && \
docker cp /data/low-altitude/backend/public/video lacomnginx1:/usr/share/nginx/html/video && \
docker cp /data/low-altitude/backend/public/override.css lacomnginx1:/usr/share/nginx/html/override.css && \
docker exec lacomnginx1 nginx -s reload
```

## 6. Docker Nginx 配置参考

容器内 Nginx 配置位于 `/etc/nginx/conf.d/default.conf`：

```nginx
server {
    listen 443 ssl;
    server_name microapp.zndkfx.com;

    ssl_certificate /etc/nginx/cert/microapp.zndkfx.com.pem;
    ssl_certificate_key /etc/nginx/cert/microapp.zndkfx.com.key;

    root /usr/share/nginx/html;
    index index.html;
    client_max_body_size 50M;

    gzip on;
    gzip_min_length 1k;
    gzip_comp_level 6;
    gzip_types text/plain text/css text/javascript application/json application/javascript application/x-javascript application/xml;

    # 前端路由 (Vue SPA)
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 代理到 Node.js 后端
    location /api/ {
        proxy_pass http://172.17.0.1:8090/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        client_max_body_size 50M;
    }

    # 上传文件代理
    location /uploads/ {
        proxy_pass http://172.17.0.1:8090/uploads/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

## 7. 常见问题排查

### 启动报错 `Error: listen EADDRINUSE`
- 端口被占用，修改启动命令中的端口：`PORT=8091`

### 前端更新后页面没变化
- 确认已执行 `docker cp` 将新文件复制到容器内
- 确认已执行 `docker exec lacomnginx1 nginx -s reload`
- 浏览器使用 `Ctrl+Shift+R` 强制刷新

### git pull 报数据文件冲突
- 运行时数据文件已加入 .gitignore，正常情况不会冲突
- 如果历史原因导致冲突：`git stash && git pull origin main && git stash pop`

### 图片无法加载 (404 Not Found)
- 检查 `backend/public/uploads` 目录是否存在且有文件
- Nginx 的 `/uploads/` 路径由 Docker 容器代理到 Node.js 后端

### 上传文件失败 (Permission denied)
- 检查目录权限：`chmod -R 755 /data/low-altitude/backend/public/uploads`

### SSO 登录失败
- 检查 `platformAuth.js` 中的配置
- 确认畅行温州平台的接口地址和密钥正确

### 服务配置页面空白
- 检查 `services_config.json` 文件大小：`wc -c backend/services_config.json`
- 如果只有 2 字节 (空的 `{}`)，需要从 git 历史恢复：
  `git show <commit>:backend/services_config.json > backend/services_config.json`
- 然后重启：`pm2 restart low-altitude-server`
