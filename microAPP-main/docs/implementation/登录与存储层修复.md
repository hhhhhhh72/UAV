**修改日期**: 2026-01-20  
**修改范围**: 后端存储层、前端登录/注册/管理页面

## 问题概述

### 问题1: 管理后台服务详情无法加载

**错误信息**:
```
TypeError: e.data.map is not a function
TypeError: n.filter is not a function
```

**根本原因**: 
- 使用 PostgreSQL 存储时，`writeJsonStore` 函数调用了 `JSON.stringify(data)` 导致双重序列化
- 数据被存储为 JSON 字符串而非 JSONB 数组
- 读取时返回字符串 `"[...]"` 而非数组 `[...]`

### 问题2: 登录页面只有授权码登录

**问题描述**:
- 登录页面仅支持授权码登录，没有账号密码登录选项
- 管理员和本地测试用户无法登录
- 授权码登录显示为手动输入方式（错误的交互设计）

### 1. 后端存储层修复

**文件**: `backend/storage.js`

#### 1.1 修复写入函数 (writeJsonStore)

```javascript
// 修改前（错误）
await query(
    `INSERT INTO json_store (key, data, updated_at)
    VALUES ($1, $2, NOW())
    ON CONFLICT (key)
    DO UPDATE SET data = EXCLUDED.data, updated_at = NOW();`,
    [key, JSON.stringify(data)]  // ❌ 双重序列化
);

// 修改后（正确）
await query(
    `INSERT INTO json_store (key, data, updated_at)
    VALUES ($1, $2, NOW())
    ON CONFLICT (key)
    DO UPDATE SET data = EXCLUDED.data, updated_at = NOW();`,
    [key, data]  // ✅ 直接传递，pg库自动处理JSONB序列化
);
```

## 授权码登录流程说明

### 正确的流程（用户无感知）

```
畅行温州APP                              低空服务平台
    │                                        │
    │  1. 用户点击"低空服务"入口               │
    │                                        │
    │  2. 平台生成临时授权码 ABC123            │
    │                                        │
    │  3. 跳转: xxx.com/?authcode=ABC123 ──────>│
    │                                        │
    │                                   4. 检测到authcode
    │                                   5. 调用后端验证
    │                                   6. 后端向畅行温州API换取用户信息
    │                                   7. 自动创建/登录用户
    │                                   8. 跳转首页
    │                                        ▼
```

### 关键点

- `authcode=xxx` 中的 `xxx` 是畅行温州平台动态生成的
- 一次性授权码，用过即失效
- 用户完全不知道这个码是什么
- 整个登录过程对用户透明
