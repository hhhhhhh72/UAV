## 一、SSO 对接流程说明

### 1.1 畅行温州 SSO 认证流程

```
┌─────────────────┐    ①点击按钮      ┌─────────────────┐
│   畅行温州App   │ ──────────────→  │  畅行温州后台    │
│   (小程序/H5)   │                   │                 │
└─────────────────┘                   └────────┬────────┘
                                              │ ②生成临时授权码(authcode)
                                              ▼
┌─────────────────┐   ③ WebView跳转   ┌─────────────────┐
│   本平台H5前端  │ ←────────────────  │ URL带authcode   │
│ microapp.zndkfx │                   │ ?jyauthcode=xxx │
└────────┬────────┘                   └─────────────────┘
         │ ④ 检测到authcode，调用后端
         ▼
┌─────────────────┐   ⑤ 用authcode请求  ┌─────────────────┐
│   本平台后端    │ ──────────────────→ │  畅行温州平台   │
│ /api/sso/login  │                     │ 会员信息查询    │
└────────┬────────┘                     └────────┬────────┘
         │                                        │ ⑥ 返回用户信息
         │ ←──────────────────────────────────────┘
         │ ⑦ 创建/匹配本地用户，生成JWT
         ▼
┌─────────────────┐
│  用户自动登录    │
│  返回token给前端 │
└─────────────────┘
```

### 1.2 关键接口说明

| 接口 | 调用方 | 说明 |
|------|--------|------|
| 畅行温州 `4.2 会员授权访问授权码获取` | 畅行温州App | 生成临时授权码 |
| 畅行温州 `4.3 会员授权访问会员信息查询` | 本平台后端 | 用authcode换取用户信息 |
| 本平台 `/api/sso/login` | 本平台前端 | SSO登录入口 |

## 二、现有问题分析

### 2.1 登录流程问题

| 问题 | 描述 | 优先级 |
|------|------|--------|
| 登录页只支持授权码 | `/login` 页面只有授权码输入，没有手机号/密码登录 | 高 |
| 注册功能禁用 | `/register` 显示"不支持本地注册" | 中 |
| 管理员无独立入口 | 管理员无法独立登录后台 | 高 |
| SSO二次登录重复验证 | 用户已登录时再次从畅行温州跳转会重复调用SSO | 中 |

### 2.2 用户场景覆盖

| 场景 | 当前状态 | 需要处理 |
|------|---------|----------|
| 畅行温州用户首次进入 | ✅ 自动创建账号并登录 | - |
| 畅行温州用户二次进入（同设备） | ⚠️ 可能重复调用SSO | 是 |
| 用户刷新页面 | ✅ Token有效则保持登录 | - |
| 用户Token过期 | ✅ Refresh Token自动续期 | - |
| 用户直接访问H5（无authcode） | ❌ 无法登录 | 看业务需求 |
| 管理员独立登录 | ❌ 缺少入口 | **必须解决** |
| 新用户独立注册 | ❌ 明确禁用 | 看业务需求 |

### 2.3 技术债务

1. **登录态存储不一致**：同时使用 `localStorage.user` 和 `authStorage.token`
2. **sessionStorage 存储 authcode**：页面刷新后清空，无法有效防止重复登录
3. **后端接口权限不统一**：部分接口未加 `authRequired` 中间件

| joininstid | `00000010` | `00000010` | ✅ 正确 |
| instid | `00000001` | `00000001` | ✅ 正确 |
| mchntid | `100000010003` | `100000010003` | ✅ 正确 |
| chnlid | `03` | `03` | ✅ 正确 |
| SM2 私钥 | `a180a91b...` | `C2993EDE...` | ❌ 需更新 |
| SM4 密钥 | `67651926...` (hex) | `1234567890123456` (utf8→hex) | ⚠️ 格式问题 |

### 4.3 ⚠️ SM4 密钥格式问题（需修复）

**当前代码问题**：
```javascript
// 当前代码假设SM4密钥是UTF-8字符串，然后转hex
const SM4_KEY_RAW = process.env.PLATFORM_SM4_KEY || '1234567890123456';
const SM4_KEY = Buffer.from(SM4_KEY_RAW, 'utf8').toString('hex');
```

**实际情况**：畅行温州提供的SM4密钥 `67651926067651926067651926067651` **已经是32位hex字符串**，可直接使用。

**修复方案**：修改 `backend/platformAuth.js`，判断密钥格式或直接使用hex字符串。
