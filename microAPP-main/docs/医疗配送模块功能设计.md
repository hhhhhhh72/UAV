# 医疗配送模块功能设计文档

> 文档版本: v1.1
> 模块名称: 医疗配送（Medical Delivery）
> 模块归属: 低空服务 > 无人机物流
> 阶段: 一期（MVP）
> 设计参考: 闪送、UU跑腿、达达快送等同城即时配送平台

---

## 一、模块定位

医疗配送模块隶属于「无人机物流」业务线，与现有「吊运作业」平级，一期定位为**同城/区域医疗物资无人机即时配送服务**，面向医院、检验中心、药房等机构用户提供标准化配送下单与订单跟踪能力。

```
低空综合服务平台
├── 后台管理
├── 前端应用 (H5 / 小程序)
├── 低空服务
│   └── 无人机物流
│       ├── 吊运作业（已有：杨梅运输、泰顺特产）
│       └── 医疗配送（本期新增）
└── 智能体能力
```

## 三、功能域详细设计

### 3.1 寄件人认证

#### 3.1.1 认证流程

```
用户发起认证
    │
    ▼
填写身份信息 ──→ 上传身份证照片（正反面）
    │               │
    ▼               ▼
签署授权协议 ←── 确认协议内容（医疗配送免责/授权条款）
    │
    ▼
提交审核 ──→ 管理端人工审核
    │               │
    ▼               ▼
认证通过/驳回 ←── 审核结果通知（短信 + 站内消息）
    │
    ▼
获得下单资格
```

#### 3.1.2 认证字段

| 字段 | 必填 | 说明 |
|------|------|------|
| 真实姓名 | 是 | 与身份证一致 |
| 身份证号 | 是 | 加密存储，仅用于审核 |
| 手机号 | 是 | 接收验证码与通知 |
| 所属机构 | 是 | 医院/检验中心/药房/其他 |
| 机构名称 | 是 | 机构全称 |
| 机构地址 | 否 | 辅助信息 |
| 职务 | 否 | 医生/护士/药师/检验师/其他 |
| 身份证正面照 | 是 | 上传图片 |
| 身份证反面照 | 是 | 上传图片 |
| 授权协议确认 | 是 | 勾选确认 |

#### 3.1.3 认证状态机

```
未认证 ──→ 待审核 ──→ 已认证
            │            │
            └────→ 已驳回
```

- **未认证**: 未提交认证信息，无法下单
- **待审核**: 已提交，等待管理端审核（24h内完成）
- **已认证**: 审核通过，可正常下单
- **已驳回**: 审核未通过，可重新提交（显示驳回原因）

#### 3.1.4 授权协议内容要点

1. 寄件人保证所寄送物品符合航空运输安全规范
2. 禁止寄送违禁品、危险品、非法物品
3. 同意平台对物品进行必要安全检查
4. 理解无人机配送受天气、空域等客观条件限制
5. 同意平台在不可抗力情况下的免责条款
6. 授权平台在配送过程中使用寄件人提供的联系信息

### 3.2 配送下单

#### 3.2.1 下单入口

- **入口1**: 首页金刚区 / 服务列表页 — 新增「医疗配送」服务入口（ID: 14）
- **入口2**: 服务详情页 — 点击后跳转专属下单流程
- **前置校验**: 进入下单页前校验用户认证状态，未认证引导至认证页

#### 3.2.3 物品拍照说明

参考闪送、UU跑腿等平台的取件拍照机制，医疗配送要求用户在下单时必须拍照物品照片：

- **必须上传**: 至少1张，最多3张物品照片
- **用途**: 确认物品包装完整、符合运输要求，作为配送安全凭证
- **拍照建议**: 拍摄包装外观、标签信息、密封状态
- **技术实现**: 复用现有 Multer 上传机制，图片压缩至 1MB 以内

#### 3.2.4 预估费用与时间

参考跑腿平台的实时计价展示，一期仅作展示不做实际收费：

| 计价因子 | 计算规则 | 说明 |
|----------|----------|------|
| 基础费 | ¥20 | 固定起步价 |
| 距离费 | ¥6/km | 根据起降场直线距离计算 |
| 时效加价 | 普通×1.0 / 加急×1.5 / 特急×2.0 | 按紧急程度倍率 |
| 温控加价 | 冷藏+¥10 / 冷冻+¥20 | 有温控要求时加收 |

> ※ 一期计价仅为展示用途，不实际收费。二期接入支付后启用真实计价。

预估送达时间计算：

| 紧急程度 | 接单响应时间 | 起飞准备 | 飞行速度参考 |
|----------|------------|----------|------------|
| 普通 | 30分钟内接单 | 20分钟 | 60km/h |
| 加急 | 15分钟内接单 | 10分钟 | 60km/h |
| 特急 | 5分钟内接单 | 5分钟 | 60km/h |

#### 3.2.5 地图选点交互

- 页面内嵌 Leaflet 地图组件
- 地图标注所有**已启用**的起降场（图标区分出发/到达）
- 用户点击地图上的起降场图标进行选择
- 选择后显示起降场名称、地址、距离信息
- 不支持自由坐标点输入，仅能从预设列表中选择
- 出发与到达不能选择同一地点

#### 3.2.6 下单校验规则

| 校验项 | 规则 |
|--------|------|
| 寄件人认证 | 必须为「已认证」状态 |
| 手机号格式 | 中国大陆手机号正则校验 |                                                                                    
| 起降场选择 | 出发≠到达，且均为启用状态 |
| 物品类型 | 至少选择一项 |
| 预估重量 | 0.1kg ~ 10kg（一期设备载重上限） |
| 紧急程度 | 必选 |
| 物品拍照 | 至少1张，最多3张，单张≤ 5MB |
| 运营时间 | 下单时间需在起降场运营时间范围内 |
| 超重检查 | 物品重量不得超过起降场最大承重 |

#### 3.2.7 再次下单（快捷复制）

参考跑腿平台的「再来一单」功能，医疗场景中样本转运等多为高频重复操作：

- **入口**: 订单详情页底部「再次下单」按钮（已完成/已取消订单可见）
- **复制字段**: 寄件人信息、取货人信息、起降场选择、物品类型、温控要求
- **不复制**: 物品拍照、物品描述、紧急程度（需重新确认）
- **交互**: 跳转下单页并自动填充，用户确认后提交

#### 3.3.1 起降场数据结构

#### 3.3.2 管理端功能

- **删除起降场**: 软删除（已有关联订单的不可删除）

### 3.4 订单管理

#### 3.4.1 订单状态流转

```
┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
│ 待接单   │ ──→ │ 已接单   │ ──→ │ 待取件   │ ──→ │ 配送中   │ ──→ │ 已送达   │ ──→ │ 已完成   │
└────┬────┘     └─────────┘     └─────────┘     └─────────┘     └────┬────┘     └─────────┘
     │                                                           │
     │         ┌─────────┐                                     │
     └───────→ │ 已取消   │ ←─────────────────────────┘
               └─────────┘     （取货人超时未取件可取消）

     ┌──────────────────────────────────────────────────────┐
     │  异常分支: 任一状态下均可标记「异常」                  │
     │  待接单 ──→ 异常/已取消                               │
     │  已接单 ──→ 异常                                     │
     │  配送中 ──→ 异常/已取消                               │
     └──────────────────────────────────────────────────────┘
```

> **说明**: 相比原方案新增了「待取件」状态，参考跑腿平台的“待取件 → 已取件 → 配送中”流程，更贴合医疗物资需要到场打包确认的实际场景。

#### 3.4.2 状态说明与操作权限

| 状态 | 状态码 | 说明 | 可操作角色 | 允许操作 |
|------|--------|------|-----------|----------|
| 待接单 | pending | 用户已下单，等待管理端确认 | 用户/管理端 | 接单、用户取消、标记异常 |
| 已接单 | accepted | 管理员已确认，准备安排配送 | 管理端 | 确认取件、标记异常、取消 |
| 待取件 | pickup | 配送员到达出发起降场，等待取件 | 管理端 | 确认取件并开始配送、标记异常 |
| 配送中 | delivering | 无人机已起飞执行配送 | 管理端 | 确认送达、标记异常 |
| 已送达 | delivered | 物品已到达目的起降场 | 管理端 | 确认完成、取消（限时） |
| 已完成 | completed | 取货人已确认取件，订单结束 | — | 仅查看、可评价 |
| 已取消 | cancelled | 订单被取消（主动/超时/异常） | — | 仅查看、可再次下单 |
| 异常 | exception | 配送过程中出现异常情况 | 管理端 | 恢复/重新安排/取消 |

#### 3.4.3 异常类型

| 异常代码 | 异常类型 | 说明 |
|----------|----------|------|
| WEATHER | 天气原因 | 大风/雷雨/大雾等不适宜飞行 |
| EQUIPMENT | 设备故障 | 无人机或起降场设备故障 |
| AIRSPACE | 空域限制 | 临时空域管制或禁飞 |
| ITEM_ISSUE | 物品问题 | 物品不符合运输要求或包装破损 |
| RECEIVER | 取货人问题 | 取货人失联或拒绝取货 |
| OTHER | 其他 | 其他不可控因素 |

#### 3.4.4 订单列表（C端 — 我的订单）

- 展示当前用户发起的所有配送订单
- 支持按状态筛选（全部/待接单/配送中/已完成/已取消）
- 列表项展示：订单号、状态标签、起降场信息、下单时间、紧急程度标签
- 点击进入订单详情页，查看完整信息与状态变更记录
- 订单卡片支持快捷操作：
  - 待接单订单：可取消、可电话联系客服
  - 已完成订单：可评价、可再次下单
  - 已取消订单：可再次下单

#### 3.4.5 订单列表（管理端）

- 展示所有配送订单，支持分页、筛选、搜索
- 筛选条件：状态、紧急程度、时间范围、起降场
- 搜索：订单号、寄件人姓名/手机号
- 列表项：订单号、寄件人、取货人、起降场、状态、紧急程度、下单时间
- 操作列：接单/详情/标记异常/一键联系
- 导出功能（Excel）
- 待接单数量角标提醒（参考跑腿平台新订单提醒）

#### 3.4.6 取消规则与退单机制

参考闪送、UU跑腿等平台的取消策略，明确各阶段取消规则：

| 订单状态 | 取消方 | 取消规则 | 说明 |
|----------|--------|----------|------|
| 待接单 | 用户 | ✅ 可自由取消 | 未接单前用户可随时取消，无任何限制 |
| 待接单 | 管理端 | ✅ 可取消 | 管理端拒接订单，需填写取消原因 |
| 已接单 | 用户 | ⚠️ 有条件取消 | 接单后10分钟内可免责取消，超过需联系管理员 |
| 已接单 | 管理端 | ✅ 可取消 | 需填写取消原因，通知用户 |
| 待取件 | 用户 | ❌ 不可取消 | 已安排配送，用户不可自主取消 |
| 待取件 | 管理端 | ✅ 可取消 | 物品问题或用户请求，管理员可取消 |
| 配送中 | 用户 | ❌ 不可取消 | 无人机已起飞，无法中途取消 |
| 配送中 | 管理端 | ⚠️ 仅异常可取消 | 仅在异常情况下可强制取消 |
| 已送达 | 管理端 | ⚠️ 限时取消 | 取货人超过2小时未取件，可取消 |

**取消操作要求**：
- 取消时必须填写取消原因（选择 + 自定义）
- 取消后自动通知双方（寄件人 + 取货人）
- 取消记录保留在订单时间线中

**取消原因选项**：
- 不需要了
- 信息填写错误，重新下单
- 等待时间过长
- 找到其他配送方式
- 其他原因（填写）

#### 3.4.7 超时自动处理机制

参考跑腿平台的超时自动提醒与取消策略：

| 超时场景 | 超时时间 | 自动处理 | 通知对象 |
|----------|----------|----------|----------|
| 待接单超时 | 普通30min / 加怅15min / 特急5min | 自动提醒管理员，超过后可自动取消 | 管理员 + 用户 |
| 已接单未配送 | 接单后60min未开始配送 | 自动提醒管理员 | 管理员 |
| 已送达未取件 | 送达后2小时未确认取件 | 短信提醒取货人，超过4h自动标记异常 | 取货人 + 管理员 |
| 异常未处理 | 标记异常后24h未处理 | 升级提醒高级管理员 | 高级管理员 |

**实现策略**：
- 一期采用定时任务扫描（每5分钟检查一次超时订单）
- 超时提醒记录在订单时间线中
- 管理端待处理列表高亮超时订单（红色标记）

#### 3.4.8 一键联系功能

参考跑腿平台在订单详情中提供的联系能力：

### 3.7 评价系统

#### 3.7.1 评价规则

| 差评(1-2星) | 配送超时、包装破损、服务态度差、没有通知 |

## 九、合理性评估

### 9.1 业务合理性

| 评估维度 | 结论 | 说明 |
|----------|------|------|
| 市场需求 | ✅ 合理 | 医疗物资无人机配送是低空经济核心场景之一，血液、检验样本等时效性要求高 |
| 场景聚焦 | ✅ 合理 | 一期聚焦「同城点对点半自动化配送」，不涉复杂调度，降低实现难度 |
| 用户角色 | ✅ 合理 | 寄件人+取货人双角色，符合医疗机构间样本转运的实际流程 |
| 认证要求 | ✅ 合理 | 医疗物资涉及安全合规，实名认证+授权协议是行业通行做法 |
| 状态流转 | ✅ 合理 | 待接单→已接单→配送中→已送达→已完成，符合物流配送通用模型 |

### 9.2 技术合理性

| 评估维度 | 结论 | 说明 |
|----------|------|------|
| 架构兼容 | ✅ 合理 | 复用现有 Express + Vue3 + Vant4 + JSON存储 架构，新增模块无架构冲突 |
| 地图选点 | ✅ 合理 | 现有 Leaflet 可直接复用，预设坐标点模式降低了GIS复杂度 |
| 数据模型 | ✅ 合理 | 6个新数据存储key（订单/认证/起降场/短信/联系人/评价），结构清晰 |
| 短信通知 | ⚠️ 注意 | 需额外申请短信服务商账号与模板审核，建议开发环境先日志模拟 |
| 文件上传 | ✅ 合理 | 身份证/物品拍照上传复用现有 Multer + 上传目录机制 |
| 订单并发 | ⚠️ 注意 | JSON文件存储模式下，订单接单存在并发覆盖风险，需加文件锁或迁移至数据库 |
| 超时机制 | ✅ 合理 | 定时任务扫描实现简单，复用 Node.js setInterval 或 node-cron |
| 预估计价 | ✅ 合理 | 纯前端计算展示，无后端复杂度，二期迁移至后端计价服务 |

| 依赖项 | 风险等级 | 应对策略 |

| 身份证OCR识别 | 低 | 一期不做OCR，人工审核为主，用户手动填写信息 |
| 身份证加密存储 | 低 | 使用对称加密（AES）存储，密钥配置在环境变量 |
| 并发订单处理 | 中 | JSON文件存储有并发风险，建议关键操作用文件锁或考虑迁移PostgreSQL |
| 无人机真实对接 | 高 | 一期为人工调度，不对接真实无人机飞控，仅做订单状态管理 |

### 10.3 合规性考量

| 合规项 | 状态 | 说明 |
|--------|------|------|
| 个人信息保护 | ⚠️ 需关注 | 身份证、手机号需加密存储，符合《个人信息保护法》 |
| 医疗物品运输规范 | ⚠️ 需关注 | 需明确配送物品类型限制，血液/样本需符合生物安全运输要求 |
| 航空器运营资质 | ⚠️ 需关注 | 实际执飞需运营方持有《民用无人驾驶航空器运营合格证》 |
| 空域审批 | ⚠️ 需关注 | 实际飞行需提前申请空域，一期系统层面只做记录不做自动审批 |

## 十一、实施建议

### 11.1 优先级实施顺序

```
第1周：
  ├── 起降场管理（管理端）—— 基础数据准备
  ├── 寄件人认证申请（H5）
  ├── 认证审核（管理端）
  └── 常用联系人管理（H5）

第2周：
  ├── 配送下单（H5：寄件/取货信息 + 地图选点 + 物品拍照）
  ├── 预估费用与时间展示
  ├── 订单创建与详情查询
  └── 我的订单列表（C端）

第3周：
  ├── 订单状态流转（管理端接单、待取件、配送中、已送达、已完成）
  ├── 取消规则实现（各阶段取消逻辑）
  ├── 异常处理
  ├── 超时自动处理任务
  └── 短信通知接口预留 + 日志模拟

第4周：
  ├── 再次下单功能
  ├── 一键联系功能
  ├── 评价系统（P2，可延后）
  ├── 服务入口集成（首页、服务列表、详情页）
  ├── 端到端联调
  └── 测试与Bug修复
```

### 11.2 关键决策点

| 决策项 | 建议方案 | 理由 |
|--------|----------|------|
| 数据存储 | 复用 JSON 文件存储，订单表加文件锁 | 与现有架构保持一致，降低迁移成本 |
| 服务入口ID | 使用 `id: 14` | 现有服务ID最大为13，医疗配送作为14号服务 |
| 短信服务 | 一期先预留接口，日志输出内容 | 避免阻塞开发进度，生产环境再接入 |
| 认证审核 | 管理端人工审核 | 一期认证量不大，人工审核更准确 |
| 支付功能 | 一期不做，仅展示预估费用 | MVP阶段先跑通配送流程，支付放到二期 |
| 取消规则 | 参考跑腿平台分阶段取消策略 | 明确各状态取消权限，减少纠纷 |
| 超时机制 | 定时任务扫描 + 自动提醒 | 简单可靠，无需引入消息队列 |
| 评价系统 | P2优先级，可第4周实现或延后 | 不阻塞核心流程，体验优化项 |
| 物品拍照 | 必须上传1-3张 | 医疗物资配送安全凭证，参考跑腿取件拍照机制 |

## 十二、验收标准

### 12.1 功能验收

- [ ] 寄件人可完成实名认证申请并查看审核状态
- [ ] 认证通过的寄件人可在地图上选择起降场并提交配送订单
- [ ] 下单时必须上传1-3张物品拍照
- [ ] 下单时可从常用联系人快速选择填充
- [ ] 下单页面展示预估费用与送达时间
- [ ] 管理端可查看待接单列表并进行接单操作
- [ ] 订单状态可按「待接单→已接单→待取件→配送中→已送达→已完成」正常流转
- [ ] 订单状态变更时，系统记录操作日志与时间线
- [ ] 管理端可对订单标记异常并填写异常原因
- [ ] C端用户可查看自己的订单列表与详情
- [ ] 待接单状态下用户可自由取消订单
- [ ] 已接单状态下用户堆10分钟内可取消，超过不可取消
- [ ] 配送中/待取件状态下用户无法取消
- [ ] 已完成/已取消订单可「再次下单」并自动填充信息
- [ ] 超时未接单的订单自动提醒管理员
- [ ] 管理端订单详情可一键联系寄件人/取货人

### 12.2 性能验收

- [ ] 订单创建接口响应时间 < 500ms
- [ ] 订单列表查询响应时间 < 300ms
- [ ] 地图起降场加载 < 1s（10个以内起降场）
- [ ] 图片上传（压缩后）< 2s/张
- [ ] 超时检查任务执行周期≤ 5分钟

### 12.3 安全验收

- [ ] 未认证用户无法进入下单页面
- [ ] 身份证信息加密存储，日志中不出现明文
- [ ] 订单操作需校验用户身份与权限
- [ ] 文件上传限制图片类型与大小（≤5MB）
- [ ] 取消操作校验当前订单状态是否允许取消
- [ ] 常用联系人数据仅本人可见，不可跨用户访问
