## 1 文档概述

### 1.1 适应范围

本规范适用于与移动平台的数据交互，系统接入方可参考该API进行标准化接入。  
本规范的接口以https post的形式进行发布，数据采用json格式。

### 1.2 数据类型

默认情况下，数据类型描述遵守以下规定：

| 标示代码 | 说明 |
| --- | --- |
| A | 字母a—z |
| N | 数字0—9 |
| S | 特殊字符 |
| an | 字母和数字字符 |
| as | 字母和特殊字符 |
| ns | 数字和特殊字符 |
| ans | 字母、数字和特殊字符 |
| H | 16进制形式的字符 |
| MM | 月 |
| DD | 日 |
| YY | 年（2位） |
| YYYY | 年（4位） |
| hh | 小时（24小时制） |
| mm | 分 |
| ss | 秒 |
| Obj | json对象 |
| List | json对象列表 |
| Boolean | true \| false |

未定义或未使用的域默认全部填写为：0

限制说明：

| 标示代码 | 说明 |
| --- | --- |

| C | 可选 |

## 2 消息交换说明

### 2.1 数据传输约定

数据交互必须遵循以下约定：

1. 通信方式为https,使用POST方式提交请求参数，字符集UTF-8，数据的格式为json格式。  
2. 通讯使用短链接。  
3. 连接超时，由于传输物理介质的不可靠性，会出现连接超时的情况。客户端和服务段都必须设置超时中断。超时时间设置在30s－60s之间。  
4. 报文中的数据区分大小写,为防止错误，所有字段名-键都小写。  
5. 所有的数据字典传输时，仅传输“取值”字段，接收方收到报文后各自根据数据字典来解析。  
6. 完整的（年月日时分秒）时间格式统一为“YYYYMMDDhhmmss”，且小时采用24小时制。例如当前时间为2017年2月3号晚上6点7分8秒，正确的为“20170203180708”，错误的为“20170203060708”。  
7. 仅需时分秒的时间格式统一为“hhmmss”，且小时采用24小时制。假如当前是下午6点7分8秒，那么正确的为“180708”，错误的“060708”。  
8. 金额的单位统一为分。
