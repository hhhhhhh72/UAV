# 上线部署清单

生产服务器：`ubuntu@api.cqnarc.cn`（腾讯云），本机已配置 SSH 免密（`C:/Windows/System32/OpenSSH/ssh.exe`）。
部署方式：**源码包覆盖 + docker compose 重建**（服务器 `~/UAV` 不是 git 仓库）。

完整架构与容器说明见 [Docker部署.md](Docker部署.md)。

## 0. 部署前本地验证（必须全绿）

```bash
go build ./... && go vet ./...      # 后端编译 + 静态检查
go test ./internal/... -count=1     # 全量测试（需本地 PG 127.0.0.1:5433）
cd frontend && npm run build        # 前端生产构建（Arco 按需导入产物）
git status -s                       # 确认工作区干净、已推送 master
```

## 1. 服务器备份（回滚保险，先做）

```bash
ssh ubuntu@api.cqnarc.cn
bash ~/UAV/deploy/db-backup.sh                # ① 数据库 pg_dump（存入 ~/UAV-db-backups/）
sudo docker tag uav-api uav-api-pre-$(date +%Y%m%d-%H%M%S)   # ② 旧镜像打标
tar -czf ~/UAV-backups/uav-code-$(date +%Y%m%d-%H%M%S).tar.gz \
  --exclude=frontend/node_modules --exclude=frontend/dist --exclude=miniprogram/unpackage -C ~ UAV   # ③ 代码归档
cp -a /var/www/admin ~/admin.bak.$(date +%Y%m%d-%H%M%S)      # ④ 前端 webroot 备份
```

## 2. 打包上传代码

```bash
# 本地
git archive --format=tar.gz -o deploy-master.tar.gz HEAD     # 只含 git 跟踪文件，天然排除 .env/node_modules
scp deploy-master.tar.gz ubuntu@api.cqnarc.cn:~/deploy-master.tar.gz

# 服务器
cd ~/UAV && tar -xzf ~/deploy-master.tar.gz                   # 覆盖代码，保留服务器独有文件（users.json 等）
```

## 3. 更新服务器 .env（`~/UAV/.env`）

必填键（缺失会导致 compose 或生产配置校验失败）：

| 键 | 说明 |
|----|------|
| `AUTH_SECRET` | JWT 签名密钥（已存在则保留） |
| `ENCRYPTION_KEY` | AES-256-GCM 密钥，`openssl rand -base64 32` |
| `SIGNING_SECRET` | 合同 webhook 签名密钥，`openssl rand -hex 32`；**生产 config 硬校验必填** |
| `WECHAT_APPID` / `WECHAT_APPSECRET` | 小程序登录（生产硬校验必填） |
| `ENV` | 固定 `production`（错误信息脱敏 + 严格配置校验） |
| `SUPER_ADMIN_PHONE` | 超级管理员手机号（如需） |
| `BASE_URL` / `CORS_ORIGINS` | 图片 URL 补全 / CORS 来源 |

> 注意：`DATABASE_URL` 容器内由 compose 固定为 `db:5432`，.env 里的宿主机视角连接串仅供本地工具使用。

## 4. 重建并启动（迁移自动执行）

```bash
cd ~/UAV && sudo docker compose up -d --build
```

- 新迁移（`migrations/0000XX_*.up.sql`）在 API 启动时自动应用，失败会直接退出
- 端口安全：db 仅回环 `127.0.0.1:5433`，api 建议也仅回环 `127.0.0.1:8080`（nginx 反代）

## 5. 上线验证清单

```bash
sudo docker ps | grep uav-              # 两个容器均 healthy
sudo docker logs uav-api-1 2>&1 | tail  # "migrations applied"，无 panic/error
sudo docker exec uav-api-1 printenv ENV SIGNING_SECRET | wc -c   # production / 65
sudo docker exec -i uav-db-1 psql -U drone -d drone_platform -c \
  'SELECT max(version) FROM schema_migrations;'                  # = 最新迁移号
curl -s https://api.cqnarc.cn/healthz   # {"checks":{"database":"up",...},"status":"ok"}
# 端点抽查（期望码：200 / 401 / 405；404 = 路由未注册）
curl -s -o /dev/null -w '%{http_code}\n' https://api.cqnarc.cn/api/v1/demands
curl -s -o /dev/null -w '%{http_code}\n' https://api.cqnarc.cn/api/v1/admin/token   # 应为 404
```

## 6. 前端发布（管理后台）

```bash
# 本地构建后
scp -r frontend/dist ubuntu@api.cqnarc.cn:~/admin-dist-new
# 服务器：备份已做（见第 1 步④），直接同步
rsync -a --delete ~/admin-dist-new/ /var/www/admin/
# 验证
curl -sI https://api.cqnarc.cn/ | head -1          # 200
curl -s https://api.cqnarc.cn/ | grep -oE 'index-[A-Za-z0-9_-]+\.js'   # 新产物 hash
curl -sI https://api.cqnarc.cn/QyhAYrdnQ3.txt      # 微信域名校验文件必须 200，勿删
```

## 7. 小程序发布（需人工，无法脚本化）

1. 本机 HBuilderX 打开 `miniprogram/` → 运行/发行编译（dev 构建看效果，发布用正式构建）
2. 微信开发者工具导入 `unpackage/dist/dev/mp-weixin`（或发行产物）→ 上传
3. 微信公众平台提交审核 → 通过后发布

## 8. 回滚

| 层 | 回滚方法 |
|----|----------|
| API | `sudo docker tag uav-api-pre-<ts> uav-api && sudo docker compose up -d api` |
| 代码 | 解包 `~/UAV-backups/uav-code-<ts>.tar.gz` 覆盖 `~/UAV` 后重建 |
| 数据库 | `zcat ~/UAV-db-backups/uav-db-<ts>.sql.gz | sudo docker exec -i uav-db-1 psql -U drone -d drone_platform`（**会丢失之后的数据，仅紧急时用**） |
| 前端 | `rsync -a --delete ~/admin.bak.<ts>/ /var/www/admin/` |

## 9. 日常运维

- 备份 cron 已配置：`0 3 * * * ~/UAV/deploy/db-backup.sh`（保留 14 份，日志 `~/UAV-db-backups/backup.log`）
- 证书自动续期：`.acme.sh` cron 已配置
- 日志：`docker logs uav-api-1`（滚动查看）；`~/UAV/logs/`（文件轮转）
- 定期检查：`docker ps` healthy、`docker logs` 无 error/panic、`df -h /` 磁盘余量
