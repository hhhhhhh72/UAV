# 平台建设汇报稿（技术团队 · 全公司）

> 口径：无人机产业综合服务平台全貌（非近期工作），数据为当前代码库统计快照。
> 预计时长：约 6 分钟。口播时技术名词均已替换为业务语言，可直接照念。

## 开场

各位领导、各位同事，大家好。今天由我们技术团队，把无人机产业综合服务平台建设的情况向公司做一次完整汇报。我们尽量少讲技术名词，多讲清楚两件事：**这个平台是什么、做到什么程度了，以及它对公司的价值。**

## 一、我们做的是什么

一句话：**一个覆盖无人机产业链的线上服务平台**，包含三块：

1. **微信小程序**（面向用户）：企业、协会、个人都能用的手机端，103 个注册页面，5 个主标签页（首页、供需大厅、发布、生态服务、我的），从培训考证、赛事报名、供需对接，到应急资源、政策合规、商城服务都有入口；
2. **管理后台**（面向公司内部）：40 个管理路由、50 个页面文件，管理、审批、内容发布、数据查看都在这里，是给协会和平台运营人员用的"总控制台"；
3. **后端服务**：443 条接口（生产开放 403 条、开发调试 40 条），是支撑前后端的"大脑"，目前部署在自有公网服务器（api.cqnarc.cn），小程序已经能真实访问。

业务范围按无人机产业链划分，覆盖 **7 大系统**：会员资源、供需对接、产学研协同、合规政策、人才教育、活动品牌、低空应急。协会的 8 级权限体系也已实现（会长、副会长、部门负责人、会员单位等各级别权限不同）。

## 二、做到什么程度（数据说话）

| 项目 | 数据 |
|---|---|
| 小程序页面 | 103 个注册页面，5 个主标签，6 个分包 |
| 管理后台 | 40 个管理路由、50 个页面文件 |
| 后端接口 | 443 条（生产开放 403 条） |
| 数据库表 | 85 张（96 组迁移） |
| 后端代码 | 209 个 Go 文件（106 个业务代码 + 99 个测试 + 4 个入口） |
| 自动化测试覆盖率 | 约 46% |
| 安全整改 | 25 处 |

翻译成大白话：**这不是一个演示模型，是一个已经上线、已经部署、可以真实注册登录和使用的产品。** 每次改动代码都要跑全套自动化测试，编译和检查全绿才允许上线；手机号、身份证等敏感数据全部加密存储；登录、审批、短信防爆破等安全机制已按要求补齐。可以说，技术侧已经具备对外试运营的条件。

## 三、对公司意味着什么

1. **从"规划"到"资产"**：平台从文档和原型，变成了可运营的产品，公司有了自己的线上阵地，而不是依赖第三方。
2. **7 大业务系统一个平台承载**：培训、赛事、需求、服务、合规、应急、内容，不用每个条线各建一套系统，数据还能互通（比如注册过的企业，培训、对接、服务端都能识别）。
3. **交付质量有保障**：约 46% 的自动化测试覆盖率、代码红线 0 违规、25 处安全整改、生产环境双容器部署 + 定时备份，这个体量的系统已经按行业正规标准来做。
4. **4 人完成全栈交付**：从数据库、接口、后台到 100 多个页面，由我们 4 个人的团队完整闭环交付。

## 四、每个人干了什么

我们技术团队一共四个人，按业务切成四块：

**1. 佘平 后端 + 管理后台 + 质量与上线**
- 整个后端系统：106 个业务代码文件 + 99 个自动化测试文件，443 条接口，85 张数据库表（96 组迁移）；
- 管理后台全部 50 个页面文件（40 个管理路由）；
- 用户看不到但更重要的部分：安全整改 25 处（登录令牌、数据加密、防爆破、防重定向、权限门禁等）、测试与 CI 体系（每次改动自动跑全套测试）、生产部署与运维（Docker 双容器、nginx 加固、数据库定时备份、公网域名上线）；
- 公共层统一维护：小程序共享组件 22 个、公共工具 18 个、页面注册表。

**2. 叶思鳞（小程序·供需撮合线）= 16 个页面文件**
- 供需大厅、需求发布、意向对接（发布方收意向/登记金额）、我的收藏、智能匹配、我的发布、订单与申请；
- 这是平台的"生意线"：客户把需求发出来，有人接、有人谈、能闭环。

**3. 李昱叡（小程序·业务线）= 40 个页面文件**
- 培训认证（课程列表/详情/报名/我的报名/证书）、低空研学、专家智库、求职招聘（发布岗位/投递/简历）、认证飞手、我的（登录注册/实名/设置/消息/订单）、应急资源；
- 这是平台的"用户线"：学员、飞手、求职者天天用的功能都在这；
- 另：做了一件跟小程序无关的事——优化了公司内部在用的钉钉多维表格（内部使用，效率提升）。

**4. 郭哲畅（小程序·内容生态线 + 文档）= 51 个页面文件 + 29 份文档**
- 生态服务全部内容页：企业案例、科技成果、研发难题、赛事活动、院校展示、品牌展示、展会排期、商城、合规政策、知识库、团体标准、测试场地、行业报告等；
- 项目全部文档（架构、接口、数据模型、开发规范、部署手册、验收清单）也由 D 维护。

**四个人的活合计**：小程序 103 个注册页面、后台 50 个页面文件、443 条接口、85 张表，另加 22 个共享组件——全公司 4 个人，从数据库到用户点到的每一个按钮，全部自主完成。

**除此之外，团队还整体完成了两件大事**：
1. 20 多个列表页的筛选体验统一改造（搜索、分类 tab、下拉面板，全平台操作一致性）；
2. 全站视觉规范落地（品牌蓝青配色、卡片体系、CSS 图标无 emoji、动效统一）。

## 五、还需要公司支持

1. **第一批真实数据**：目前系统是空的。需要业务/运营同事把企业、机构、课程、需求等第一批内容录入，用户进来才有东西看、有东西用；
2. **短信与云存储预算**：报名通知、验证码需要接入正式短信服务商；量大后的图片、合同文件建议放云存储，这两项需要一点采购预算，需公司拍板；
3. **试运营与验收**：建议下周安排公司同事在手机上真机走一遍主流程，发现问题当天修；然后小范围邀请第一批真实用户试运营；
4. **一项安全待决事项**：早期代码仓库历史里曾有环境配置文件，需要清理并重新推送，涉及一次强制变更，需公司按安全要求批准。
