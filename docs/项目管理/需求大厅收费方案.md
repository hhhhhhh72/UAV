# 需求大厅收费方案（决策材料）

> 状态：**待决策**。本文档对比三种收费模式，供团队拍板；文中所有费率/金额均为**占位值**，以「待定参数」一节最终确认为准。
> 决策后按定稿方案实施（后端资金动作 + 两端 UI + 测试，一套交付）。

## 一、现状（免费阶段）

需求大厅核心闭环（当前全免费，资金字段仅记录、无资金动作）：

```
企业发布需求 → 需求大厅 + 智能匹配 → 飞手意向登记 → 企业查看意向/联系方式
→ 企业确认接单（填订单金额，预算区间校验）→ 飞手开始 → 完工传图
→ 企业验收 completed / 返工 / 取消
```

### 现有资金基建（已可用，培训学费场景在跑）

| 组件 | 说明 |
|---|---|
| `EscrowService` | 充值/冻结/释放/退款/余额/流水/幂等查询/孤儿冻结补偿（BR-9） |
| `Demand.BudgetMinFen/BudgetFen` | 需求预算区间（发布时填写） |
| `WorkOrder.AmountFen` | 工单订单金额（确认接单时填写，面议=0） |
| `Demand.OfflineAmountFen` | 线下成交金额登记（仅撮合度量） |
| 托管金充值 | 模拟通道，单笔上限 ¥20 万，已有余额/冻结/流水页 |

### 当前业务量

需求 18 / 意向 5 / 工单 1（含金额 1）/ 证书 1 —— 早期小规模，**模式定型成本低，宜早决策**。

## 二、三种模式对比

### 模式 A：成交佣金（担保交易）—— 推荐首选

**一句话**：需求撮合不收费，平台在"成交"环节抽佣；订单金额托管担保，双方都有保障。

**资金流（沿主流程）**：

```
① 发布需求            免费（获客）
② 飞手意向登记        免费（供给侧拉量）
③ 企业确认接单        填金额 → 校验余额 → 托管冻结 AmountFen（不足 402 引导充值）
④ 飞手开工→完工传图    资金保持冻结
⑤ 企业验收通过        → 结算：飞手 AmountFen×(1−佣金率) ｜ 平台 AmountFen×佣金率
   返工 → 资金继续冻结；取消 → 全额退回企业
⑥ 面议单（金额=0）    不冻结，线下结算，完工后登记 OfflineAmountFen（仅度量）
```

**计费规则**：佣金只发生在金额 > 0 且验收通过的担保单。`佣金率` 占位 **5%**（待定）。

**开发量**：中（完全复用托管金引擎，比照培训学费模式增量改造）。要点：确认接单冻结（402 引导同培训）、验收完成双笔结算（净额→飞手 + 佣金→平台账户）、取消退款、`commission_fen`/`settle_status` 幂等防双结算、两端 UI 展示净额与佣金。

**风险**：①面议单逃避抽佣（接受：线下单本就难追踪，且关闭"线下报备"会让企业转场线下）②早期成交少，佣金收入低（合理：先有成交量才有收入）③佣金率过高劝退（5% 国内市场中性偏低）。

**优点**：平台不向"进门"收费，冷启动友好；担保交易提升双边信任，是撮合平台主流模式（猪八戒/京东服务）。

### 模式 B：发布收费（信息差变现）

**一句话**：发需求按条收费（如 ¥99/条，展示 30 天），或置顶/加急加价。

**资金流**：发布时冻结/支付发布费 → 进入大厅展示；置顶位额外计费。

**开发量**：小（发布接口加费用校验 + 支付/扣除 + 置顶排序字段）。

**风险**：①早期企业少，收费即劝退 → 内容供给断裂，飞手无单可接 ②发布费与"是否有成交"脱钩，企业感受差 ③竞品（免费平台）虹吸。

**优点**：现金流最早；实施最简单；可单点试验（先免费后收费）。

### 模式 C：会员订阅（企业年费）

**一句话**：企业年费解锁权益：置顶次数、意向线索量、智能匹配优先、专属客服。

**资金流**：年费订阅 → 权益生效（需求侧权益按额度扣减）。

**开发量**：中（订阅/到期/权益额度扣减 + 管理端配置）。

**风险**：②③同 B；权益需有足够免费流量兜底，否则"花钱买空气"。

**优点**：粘性强、收入可预期；适合平台有稳定流量后的变现升级。

## 三、分期建议

| 期 | 内容 | 理由 |
|---|---|---|
| **一期（先做）** | 模式 A 担保交易 + 佣金（佣金率 5%、单笔冻结上限 ¥20 万占位） | 复用托管金，增量最小；形成"成交→抽佣"的自循环 |
| 二期 | 模式 B 发布费/置顶（可做 A/B 实测：免费引流期后择机收费） | 等一期形成真实成交量再测 |
| 三期 | 模式 C 企业会员订阅 | 流量稳定后变现升级 |

**组合判断**：A 是"平台在赚钱"，B/C 是"用户先付费"。A 与 B 冲突小于互补：A 给企业"成交才付钱"的确定性，B 提供"曝光可控"的高级感——二期可同时上。**不建议先 B 后 A**（先收费会抬高冷启动门槛，且收费后撮合成功再抽佣会双重收费观感）。
