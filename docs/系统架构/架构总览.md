# 架构总览

## 分层架构（铁律）

```
Handler  → 解析请求 / 调Service / respond或fail
            禁做: SQL查询 / 业务判断 / 直接读写库

Service  → 角色校验 / 状态机 / 调Repository接口
            禁做: http.Request / ResponseWriter / JSON编解码

Repository → SQL执行 / 数据映射 / 返回Domain对象
             禁做: 业务规则 / 权限判断 / HTTP相关
```

## 项目结构

```
cmd/api/main.go           启动入口,组装依赖
internal/
  httpapi/                路由/中间件/Handler (443 注册)
  service/                业务规则/状态机 (约 50 个 Service)
  repository/             接口定义(59)+PG/内存双实现
  domain/                 业务实体(90 struct)
  config/                 集中配置
  logger/                 结构化日志(slog)
  cache/                  内存TTL缓存(single-flight)
  middleware/             输入消毒(已挂载)
  crypto/                 AES-256-GCM
migrations/               63组迁移(up/down, 85表)
```

## 中间件链

```
请求 → 限流(100/s) → 链路追踪 → Panic恢复 → 安全头 → CORS → Token鉴权
  → 幂等去重(24h) → 管理端门禁 → 输入消毒(JSON去HTML标签) → 业务
```

## 双存储模式

| 环境 | 存储 | 触发条件 |
|------|------|------|
| 开发 | 内存 | `DATABASE_URL` 未设置 |
| 生产 | PostgreSQL | `DATABASE_URL` 已设置 |

## 角色权限

| 角色 | 权限 |
|------|------|
| `platform_admin` | 全部管理权限 |
| `association_admin` | 企业审核/内容管理 |
| `enterprise` | 发布需求/招聘/合同 |
| `individual` | 接单/求职/交易 |

协会内部细分(8级, association_members 表): 会长/副会长/秘书长/部门负责人/普通会员/副会长单位/合作院校/访客 — 与主角色分层叠加（admin=3 > partner=2 > member=1 > public=0 的可见性模型），资源台账分级浏览
