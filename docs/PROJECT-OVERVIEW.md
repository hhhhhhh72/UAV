# 无人机产业综合服务平台 — 项目总览

**最后更新**: 2026-07-21
**代码规模**: 130 条接口 | 49 张数据表 | 76 个测试 | 33 个小程序页面

---

## 一、项目定位

面向无人机产业链的**全栈服务平台**。微信小程序端供飞手和企业使用，Web 管理后台供协会管理员使用。

**核心业务流程**：商家发布无人机作业需求 → 飞手竞标报价 → 发布者选中中标者 → 双方确认成交 → 资金托管结算。

围绕这条主线，延伸出企业入驻、招聘求职、二手交易、合同签约、培训认证、保险金融等 16 个业务模块。

### 基础设施能力

| 能力 | 实现方式 |
|------|------|
| 身份认证 | HMAC-SHA256 签名的 Bearer 令牌，15 分钟过期，支持刷新令牌轮换 |
| 权限控制 | 4 级 RBAC 角色体系（平台管理员 > 协会管理员 > 企业用户 > 个人用户） |
| 流量控制 | 令牌桶算法，每秒 100 次请求上限，超限返回 429 |
| 幂等保护 | 幂等键机制，24 小时内相同请求去重，防止网络重试产生重复数据 |
| 操作审计 | 所有写操作自动记录操作者、动作、资源、结果到审计日志表 |
| 数据加密 | AES-256-GCM 信封加密手机号、身份证号、统一社会信用代码 |
| 输出脱敏 | 公开接口自动屏蔽联系方式、精确坐标，仅返回脱敏后的数据 |
| 数据存储 | 双模式：PostgreSQL（生产环境） / 内存存储（本地开发） |
| 容器部署 | Docker 多阶段构建 + docker-compose 一键启动（数据库+应用） |
| 持续集成 | GitHub Actions 自动执行编译、静态检查、单元测试、数据库集成测试 |
| 测试保障 | 76 个测试用例（含并发压力测试、极限竞态测试、端到端测试） |

## 五、环境变量说明

| 变量名 | 是否必填 | 作用说明 |
|------|:--:|------|
| `AUTH_SECRET` | ✅ 必填 | 令牌签名密钥，至少 32 个字节长度 |
| `DATABASE_URL` | 可选 | PostgreSQL 连接串，不设置则使用内存存储（仅限开发） |
| `ADMIN_DEV_MODE` | 可选 | 设为 `true` 启用管理后台面板（生产环境必须关闭） |
| `WECHAT_APPID` | 可选 | 微信小程序 AppID，用于 code2Session 登录 |
| `WECHAT_APPSECRET` | 可选 | 微信小程序 AppSecret |
| `ENCRYPTION_KEY` | 可选 | AES-256-GCM 加密密钥，不设置则明文存储敏感字段 |
| `SIGNING_SECRET` | 可选 | 签章平台回调验签密钥 |
| `CORS_ORIGINS` | 可选 | 允许的跨域来源域名，逗号分隔 |
| `LOG_DIR` | 可选 | 日志文件存储目录，默认 `./logs` |
| `LOG_LEVEL` | 可选 | 日志级别：error / warn / info / debug |
| `HTTP_ADDR` | 可选 | 服务监听地址，默认 `:8080` |

## 六、常用命令速查

```bash
# ── 本地开发 ──
set AUTH_SECRET=至少32字节的随机字符串
set ADMIN_DEV_MODE=true
go run ./cmd/api                              # 启动后端服务 → 监听 :8080

# ── 运行测试 ──
go test ./internal/...                        # 全部单元测试 (76 个)
go test -run TestConcurrent ./internal/...    # 并发压力测试 (7 个场景)
go test -run TestExtreme ./internal/...       # 极限压力测试 (1000+ 并发)
bash Test/e2e.sh                              # 端到端接口测试 (8 个场景)

# ── 代码质量 ──
go build ./...                                # 编译检查
go vet ./...                                  # 静态分析
go test -race ./internal/...                  # 竞态检测 (需 Linux)

# ── 容器部署 ──
docker-compose up -d                          # 启动 PostgreSQL + 接口服务
docker-compose down                           # 停止所有服务
```
