# 权限矩阵：谁能做什么

> **为什么有这份文档**（2026-09-18）：两级管理员到底差在哪，此前只存在于代码里。
> 运营问「协会管理员能不能退款 / 看审计 / 导出全量」时没人答得上来；改权限时也没有
> 一张能对照的表。下面列的每一条都带代码位置，可直接复核 —— 文档写错比没有文档更糟。

## 一、四个角色

| 角色代码 | 中文 | 生产账号数（2026-09-18 实测） |
|---|---|---|
| `platform_admin` | 平台管理员 | **3**（平台管理员、A、鸟咪） |
| `association_admin` | 协会管理员 | **1**（AB） |
| `enterprise` | 企业 | 1 |
| `individual` | 个人 | 6 |

常量定义：`internal/domain/models.go:24-30`。

> 协会内部那套 8 级角色（会长/副会长/秘书长…）已于迁移 `000113` 整体下线：生产 0 行数据、
> 前端零调用、8 个角色里只有 `partner` 参与过一次判定。现在只有上面这 4 个。

## 二、门禁在哪：三层，缺一不可

### 第 1 层：中间件（拦整个前缀）

`internal/httpapi/auth.go:258-269` —— `adminGate`：

```go
if strings.HasPrefix(r.URL.Path, "/api/v1/admin/") && r.URL.Path != "/api/v1/admin/token" {
    if !ok || (a.Role != RolePlatformAdmin && a.Role != RoleAssociationAdmin) { 403 }
}
```

**任何** `/api/v1/admin/*` 默认就是「两级管理员之一」，否则 403。唯一豁免是 `/api/v1/admin/token`
（开发态签发）。这一层只分「是不是管理员」，**不区分哪一级**。

### 第 2 层：Handler / Service 里逐条判定

绝大多数写操作长这样（`internal/httpapi/biz_handlers.go` 等 40+ 处）：

```go
if a.Role != domain.RoleAssociationAdmin && a.Role != domain.RolePlatformAdmin { 403 }
```

**真正拉开两级差距的是这一层** —— 见第三节。

### 第 3 层：数据级裁剪（端点放行，但按角色少给东西）

| 规则 | 位置 |
|---|---|
| 飞手**完整身份证号**只下发给平台管理员，协会管理员一律拿脱敏值 | `internal/httpapi/training.go:488-490`（`canViewPilotPII`），脱敏在 `:492-496` |
| 用户列表里的手机号一律脱敏 | `internal/httpapi/admin_users.go:26-29`（`listPhoneMasked`） |
| 用户列表绝不返回密码 hash，只返回「有没有设过密码」 | `internal/httpapi/admin_users.go:99-100` |

## 三、两级管理员的差别（核心）

### 3.1 只有平台管理员能做 —— 协会管理员一律 403

| 能力 | 端点 | 判定位置 |
|---|---|---|
| 系统配置 读 / 写 | `GET` / `POST /api/v1/admin/config` | `config_handler.go:15`、`:25` |
| 服务配置保存（H5 兼容层，会同步平台 banner/公告） | `POST /api/services/config` | `h5_compat.go:159-165` |
| 操作审计查询 | `GET /api/v1/admin/audit-logs` | `audit_handler.go:19` |
| 全量导出（CSV，绕开分页上限） | `GET /api/v1/admin/export`、`/export/demands`、`/export/enterprises`、`/export/{resource}` | `export_handler.go:51`、`:107`、`:156`、`:190` |
| 托管金对账 | `GET /api/v1/admin/escrow/reconciliation` | `escrow.go:48`（`isPlatformAdmin` 定义在 `:41`） |
| **发起退款**（钱离开平台） | `POST /api/v1/admin/payments/refunds` | `payment_refunds.go:29-32` |
| 退款单查询 | `GET /api/v1/admin/payments/refunds` | `payment_refunds.go:70` |
| 已支付充值单（发起退款时选单） | `GET /api/v1/admin/payments/paid-orders` | `payment_refunds.go:104` |
| 重置任意账号密码 | `Service.ResetPassword` | `internal/service/users.go:254-257` |
| 删除账号 | `Service.DeleteUser` | `internal/service/users.go:334-337` |
| 改任意账号角色 | `Service.ChangeRole` | `internal/service/users.go:303`；用例 `user_delete_test.go:287` |
| 飞手完整身份证（数据级） | —— | `training.go:488` |

### 3.2 协会管理员**能做**的（运营视角）

1. **业务内容管理**：企业、专家、院校、课程、证书、职位、需求、商品、服务能力、产业资源、
   合规文档、团体标准、产学研（成果/难题/课题/场地）、活动、展会、行业报告、品牌、应急资源与调度、
   消息通知、评价、案例、赛事、咨询……即 `/api/v1/admin/{资源}` 的常规 CRUD。
   对照组用例：`platform_role_matrix_test.go:37-41`（协会管理员建专家应当 201）。
2. **审核类操作**：企业审核、商品上架审核、飞手认证审核、证书审核、报名审核、评价审核。
3. **托管金的写操作**：充值 / 冻结 / 释放 —— `requireEscrowAdmin` 对**两级都放行**
   （`escrow.go:18-20`）。原因是协会自身也是经营主体，需要代收代付。
   **但「退款」不在其中**（见 3.1，退款只给平台管理员）。
4. **建普通账号**：可以建 `individual` / `enterprise` 账号，但**不得创建管理员账号**
   （`users.go:147-149`）。
5. **发布赛事**：企业、协会、平台三种角色都可以发（`biz_handlers.go:1319-1321`）。

### 3.3 用户管理是**分级**的（容易被误读成「平台专属」）

| 操作 | 平台管理员 | 协会管理员 | 位置 |
|---|:--:|:--:|---|
| 看用户列表 | ✅ | ✅ | `admin_users.go:64` |
| 建普通账号 | ✅ | ✅ | `users.go:141-143` |
| 建管理员账号 | ✅ | ❌ | `users.go:147-149` |
| 重置密码 | ✅ | ❌ | `users.go:255-257` |
| 删除账号 | ✅ | ❌ | `users.go:335-337` |
| 改角色 | ✅ | ❌ | `users.go:303` |

## 四、企业 / 个人

| | 企业 `enterprise` | 个人 `individual` |
|---|---|---|
| 需求 | 发布 / 管理自己的需求 | 应征（投意向） |
| 招聘 | 发布职位、查看投递 | 投递简历 |
| 交易 | 上架商品、发货、处理售后 | 下单、付款、申请售后 |
| 培训 / 赛事 | 发布课程、办赛（协会/平台也可） | 报名、参赛 |
| 合同 | 发起 / 签署 | —— |
| 认证 | 企业认证（待审核） | 飞手认证、证书、保险、年检 |

归属校验写在 Service 层（分层铁律），例如「只能改自己的需求」由 Service 判，Handler 不判。

## 五、前端也拦一道（但两边规则并非完全一致）

`frontend/src/router/index.js:112-116`：路由 `meta.roles` 不含当前角色 → 提示「该页面仅平台
管理员可用」并弹回看板。目前带 `roles` 的只有 4 条：`audit-logs`、`users`、`config`、`settings`。

侧栏菜单（`frontend/src/views/admin/AdminLayout.vue:212-235`）按同一份角色过滤 —— 菜单与守卫
必须一致，否则「看得到、点进去被弹回」。这个 bug 真实发生过（提交 `96a3f18`），现在两侧对齐。

> ⚠️ **已知不一致（2026-09-18 复核发现，尚未改动）**：
> `router/index.js:110-111` 的注释写「后端平台专属接口（系统配置/**用户管理**/系统设置）仅
> platform_admin」，但后端 `admin_users.go:64` 与 `users.go:141-143` 明确**允许协会管理员**
> 查看用户列表、创建普通账号（只有改密/删除/改角色是平台专属，见 3.3）。
> 也就是前端比后端更严：协会管理员在界面上进不去用户管理，但如果直接调 API 是通的。
> **这是产品决策不是 bug** —— 要收紧就改后端（`admin_users.go:64`），要放开就改前端路由
> `meta.roles`。目前保持现状，仅在此记录，免得下一个人以为其中一边写错了。

## 七、改权限时的检查清单

1. 判定写在哪一层？**归属/角色校验属于 Service**（`CLAUDE.md` 分层铁律），Handler 只解析请求。
2. 是「端点级」还是「数据级」？端点级用 403；只是少给字段就用第 3 层裁剪。
3. 前端菜单 `AdminLayout.vue` 与路由 `meta.roles` 同步改，否则又会出现「看得到点不进」。
4. 跑第 6 节的三条命令；新增 admin 路由要同步 `perm_routes_test.go` 的探针表。
