## 二、字段明细

### 1. `avatar`（头像）🔴

**现状**：`CertifiedPilot` 模型（`internal/domain/models.go:540`）、`certified_pilots` 表（迁移 `000002`）、所有接口均无 `avatar` 字段。前端无法显示真实头像，用**姓名首字 + 姓名哈希选渐变**兜底。

**改动**（三处）：
1. **迁移**：新增 `000039_certified_pilots_avatar.up.sql`
   ```sql
   ALTER TABLE certified_pilots ADD COLUMN IF NOT EXISTS avatar TEXT DEFAULT '';
   ```
2. **模型**：`CertifiedPilot` 加
   ```go
   Avatar string `json:"avatar"`
   ```
3. **接口**：`registerPilot`（申请飞手）接收 `avatar`；`listPilots` 输出它

> **说明**：头像应走文件上传（项目已有 `/uploads` 上传链路，10MB 限制 + SHA256），上传后把 URL 存到 `avatar` 字段。或前端先支持本地上传，后端存 URL。

### 2. 飞手详情单查 `GET /api/v1/certified-pilots/{id}` 🟡

**现状**：只有 `GET /certified-pilots`（列表）、`GET /certified-pilots/mine`（我的）。**没有按 id 单查**。前端详情页靠列表数据经 `storage` 传递，分享直达/深链会失败。

**改动**：`internal/httpapi/training.go` 加 handler
```go
mux.HandleFunc("GET /api/v1/certified-pilots/{id}", s.getPilot)
```
返回单个飞手（脱敏 id_card，approved 才可公开查看，其他角色鉴权）。

### 3. 列表分页 🟢

**现状**：`listPilots`（`training.go:266`）返回全量数组，无 `page/page_size` 支持。飞手数量增长后列表会卡。

**改动**：`listPilots` 支持 `page/page_size` 参数，返回分页信封（参照 `listAdminPilots` 的 `paginatedRespond`）。

### 4. `cert_ids` 关联证书详情 🟡

**现状**：飞手返回 `cert_ids: ["cert-xxx"]` 只是 ID 数组。前端详情页无法显示证书名称/类型，只能显示"驾驶证照 #N"占位。

**改动**（推荐方案）：`listPilots` / 飞手详情返回时，把 `cert_ids` **扩展为证书对象数组**：
```json
"cert_ids": ["cert-1"],
"certificates": [
  { "id": "cert-1", "cert_type": "caac", "cert_name": "CAAC无人机驾驶员执照",
    "issuer_org": "中国民航局", "level": "视距内驾驶员", "status": "approved" }
]
```
通过 `certRepo.ListByUser`（`internal/service/training.go:46` 已有）按证书 id 关联，把名称/类型/签发机构拼进响应。

> 若不想改接口结构，至少提供一个 `GET /api/v1/certificates/batch?ids=a,b,c` 供前端按 id 查证书详情。

### 5. `region`（所在地区）🟢

**现状**：模型无 `region`。前端详情页"所在地区"显示"重庆·协会名录"。

**改动**：可选。`certified_pilots` 加 `region TEXT`，申请飞手时让用户选地区。低优先级（前端已有合理兜底）。

### 6. `rating`（评分）🟢

**现状**：模型/表有 `rating DOUBLE PRECISION DEFAULT 0`，但**无写入逻辑**（申请/审核不设评分），恒为 0。前端默认显示 5.0。

**改动**：可选。若运营要录评分，管理端 `approvePilot` 时带 `rating` 参数；或后续从评价系统计算。低优先级。
