# 应急模块 · 后端待补清单

> **用途**：小程序「低空应急」模块（应急资源 `pages/emergency/resources`、救援案例 `pages/emergency/cases`、部门对接 `pages/emergency/depts`、调度记录 `pages/emergency/dispatches`）联调中发现的后端缺口，供后端一次性修复。
>
> **原则**：前端已做字段兼容与兜底，后端修复后**无需前端改动**。

## 二、问题明细

### 1. `createRescueCase` 结构体缺 json tag 🔴

**现状**：请求结构体声明为裸字段，Go 标准库解码时按字段名大小写不敏感匹配，**`event_type` 匹配不到 `EventType`**（下划线不参与 fold 匹配），`drone_model`/`team_name` 同理。

```go
// internal/httpapi/batch3_handlers.go:27
var in struct{ Title, EventType, Location, DroneModel, TeamName, Summary, Result, Lessons, Source, Date string }
```

`Title`/`Location`/`Summary` 等单字段能解码，所以案例的标题、地点、经过正常，唯独三个复合字段丢失。

**改动**（1 处）：

```go
var in struct {
    Title      string `json:"title"`
    EventType  string `json:"event_type"`
    Location   string `json:"location"`
    DroneModel string `json:"drone_model"`
    TeamName   string `json:"team_name"`
    Summary    string `json:"summary"`
    Result     string `json:"result"`
    Lessons    string `json:"lessons"`
    Source     string `json:"source"`
    Date       string `json:"date"`
}
```

**前端当前规避**：seed 脚本 `scripts/seed_test_data.py` 发无下划线 key（`eventtype`/`dronemodel`/`teamname`）绕开。后端修复后 seed 的 key 应改回 snake_case（脚本内已有注释说明）。

> **建议**：顺手检查同类 `create*` handler 是否同样缺 json tag（`createEmergencyDept`、`createEmergencyDrill` 已有 tag 正常）。

### 2. `createEmergencyDispatch` 不接收 status 🟡

**现状**：创建调度时请求体不解析 `status`，Service 创建后 status 固定为 `dispatched`：

```go
// internal/httpapi/biz_handlers.go:1480
d, err := s.emergencySvc.CreateDispatch(in.ResourceID, in.EventDesc, in.Location, in.Commander, in.Result, startTime, endTime)
```

**改动**（2 处）：
1. 请求结构体加 `Status string \`json:"status"\`` 并传给 `CreateDispatch`
2. （可选）`EmergencyDispatchService.CreateDispatch` 加 status 参数，或创建后默认 `pending`

**前端当前规避**：seed 脚本创建后用 `PUT /api/v1/admin/emergency-dispatches/{id}` 更新状态（该接口已接收 status）。

### 3. `createEmergencyDrill` 结构体缺 json tag 🟡

**现状**：与问题 1 同类，`dept_id`/`drone_count` 两个 snake_case 字段创建时被丢弃（`participants` 因单字段侥幸能解码）：

```go
// internal/httpapi/batch3_handlers.go:54
var in struct{ DeptID, Title, Scenario, Date, Result string; Participants, DroneCount int }
```

**改动**（1 处）：

```go
var in struct {
    DeptID      string `json:"dept_id"`
    Title       string `json:"title"`
    Scenario    string `json:"scenario"`
    Date        string `json:"date"`
    Participants int   `json:"participants"`
    DroneCount  int    `json:"drone_count"`
    Result      string `json:"result"`
}
```

**前端当前规避**：seed 脚本用无下划线 key（`deptid`/`dronecount`）写入。

**前端状态值域**（`miniprogram/pages/emergency/dispatches.vue`）：
`pending`（待响应）/ `ongoing`（进行中）/ `completed`（已完成）/ `cancelled`（已取消）
（后端 `listEmergencyDispatches` 注释已说明兼容 `pending/dispatched/completed/ongoing/done/cancelled`）

### 4. `listEmergencyResources` 忽略 `res_type` / `q` 参数 🟡

**现状**：`listEmergencyResources`（`biz_handlers.go:1381`）只调 `ListResources(page, pageSize)`，不读取 query 里的 `res_type`（分类）和 `q`（搜索关键词）。前端 `resources.vue` 顶部 6 个分类 tab（全部/无人机/通讯/车辆/医疗/救援）和搜索框都向后端传这两个参数，但被静默忽略。

```go
// internal/httpapi/biz_handlers.go:1381
func (s *Server) listEmergencyResources(w http.ResponseWriter, r *http.Request) {
    page, pageSize := paginationFromQuery(r)
    items, total, err := s.emergencySvc.ListResources(page, pageSize) // ← 未传 res_type / q
    ...
}
```

**影响**：应急资源页的分类 tab 筛选、关键词搜索在后端不生效，返回全量分页数据；数据量大时分页内结果与筛选意图不符。

**改动**：解析 `res_type`、`q` 并透传 `EmergencyService.ListResources` → `EmergencyRepository.ListResources`，在 SQL/内存层过滤后再分页。

### 5. `listEmergencyDispatches` 的 status 筛选为「当前页内过滤 + 精确匹配」 🟡

**现状**：handler 先 `ListDispatches(page, pageSize)` 拿到**当前页**，再在内存里 `d.Status == status` 精确过滤（`biz_handlers.go:1433`）。两个问题：① 过滤发生在分页之后，跨页数据漏掉；② 精确匹配导致前端值域 `ongoing` 匹配不到库里实际存的 `dispatched`。

```go
// internal/httpapi/biz_handlers.go:1433
if status := r.URL.Query().Get("status"); status != "" {
    var out []domain.EmergencyDispatch
    for _, d := range items {            // ← 只遍历当前页
        if d.Status == status { ... }    // ← 精确匹配，dispatched ≠ ongoing
    }
}
```

**影响**：`dispatches.vue` 的 4 个状态 Tab 无法可靠依赖后端筛选，前端被迫 `fetchList` 一次拉全量、`computed list` 客户端过滤（见 dispatches.vue 内注释）。

**改动**：status 下沉到 repo 层 SQL 过滤（先全量过滤再分页）；统一值域——`dispatched` 归并为 `ongoing`（或前后端对齐枚举 `pending/ongoing/completed/cancelled`）。

### 6. `listEmergencyDispatches` 不支持 `resource_id` 查询参数 🟡

**现状**：`listEmergencyDispatches` 只解析 `page`/`page_size`/`status`，无 `resource_id` 过滤。

**影响**：`resources.vue` 详情抽屉的「调度记录」需拉全量调度（`page_size:50`）再前端按 `resource_id` 过滤（见 `loadDispatches`），调度记录超过 50 条时该资源的记录会被截断漏掉。

**改动**：支持 `resource_id` 查询参数，repo 层按 `resource_id` 过滤。

### 7. 调度记录未内嵌关联资源 🟡

**现状**：`domain.EmergencyDispatch` 无关联资源字段，`listEmergencyDispatches` 只返回调度记录自身。

**影响**：`dispatches.vue` 详情「关联资源」区块需额外 `GET /api/v1/emergency-resources`（`page_size:100`）拉全量再按 `resource_id` 匹配（见 `fetchResources` / `relatedResources`），资源多时浪费流量且可能截断。

**改动**：`listEmergencyDispatches` 返回时内嵌关联资源（按 `resource_id` join），或提供「批量按 id 查资源」接口供前端调用。

## 三、验收标准

```bash
# 1. 编译 + 测试
go build ./... && go vet ./... && go test ./internal/...

# 2. 创建救援案例含三字段，回读确认
POST /api/v1/admin/rescue-cases
  { "title": "测试案例", "event_type": "mountain_fire", "location": "重庆",
    "drone_model": "M300", "team_name": "测试队", "date": "2026-08-01T00:00:00Z", ... }
GET /api/v1/rescue-cases   # 返回 event_type / drone_model / team_name 非空

# 3. 创建调度指定状态，回读确认
POST /api/v1/admin/emergency-dispatches
  { "resource_id": "...", "event_desc": "测试", "status": "pending", ... }
GET /api/v1/emergency-dispatches   # 返回 status = pending

# 4. 创建演练含 dept_id/drone_count，回读确认
POST /api/v1/admin/emergency-drills
  { "dept_id": "...", "title": "测试演练", "participants": 20, "drone_count": 5, ... }
GET /api/v1/emergency-drills   # 返回 dept_id / drone_count 非空

# 5. 资源分类/搜索：按 res_type + q 过滤后再分页
GET /api/v1/emergency-resources?res_type=drone&q=侦察   # 仅返回匹配项，total 为过滤后总数

# 6. 调度状态筛选：跨页返回全部匹配（含 dispatched 归并 ongoing）
GET /api/v1/emergency-dispatches?status=ongoing&page=1&page_size=10   # 返回全部 ongoing（含 dispatched）

# 7. 按资源查调度：仅返回该资源记录
GET /api/v1/emergency-dispatches?resource_id=xxx   # 仅返回 resource_id=xxx 的记录

# 8. 关联资源：list 返回内嵌 related，或可批量按 id 查资源
GET /api/v1/emergency-dispatches   # 每条含 related（关联资源数组）
```
