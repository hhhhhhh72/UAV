## 二、字段明细

### 1. `location` / `start_date` / `end_date`（接口层缺失）🔴

**现状**：`study_tours` 表已有这三列（迁移 `000037`），但 `createStudyTour` / `updateStudyTour` handler **不接收**，传了也被丢弃。

**改动位置（2 处）**：
```text
internal/httpapi/admin_crud_stubs.go
├── createStudyTour()  ← 674 行起
└── updateStudyTour()  ← 695 行起
```

**改动内容**：请求结构体加三字段，并赋给 `domain.StudyTour`：

```go
var in struct {
    // ...现有字段（title/destination/duration/capacity/status/description）
    Location  string    `json:"location"`
    StartDate time.Time `json:"start_date"`
    EndDate   time.Time `json:"end_date"`
}
// 赋给 domain.StudyTour 对应字段
st.Location = in.Location
st.StartDate = in.StartDate
st.EndDate = in.EndDate
```

`domain.StudyTour`（`internal/domain/models_batch1.go:123`）**已有**三字段，无需改模型。`updateStudyTour` 的 `Update` 也应带上这三字段（当前更新会覆盖为空）。

### 2. `cover_image`（封面图）🟡

**现状**：`study_tours` 无封面图列，`StudyTour` 模型无图片字段。前端列表卡片封面、详情页 Hero 用主题渐变兜底。

**改动**（三处）：
1. **迁移**（000038 同文件追加）：
   ```sql
   ALTER TABLE study_tours ADD COLUMN IF NOT EXISTS cover_image TEXT DEFAULT '';
   ```
2. **模型**：`internal/domain/models_batch1.go` 的 `StudyTour` 加
   ```go
   CoverImage string `json:"cover_image"`
   ```
3. **接口**：create/update handler 接收 `cover_image`，convStudy 输出它

**图片存储/访问方式（项目已有机制）**：
- 上传：`POST /api/v1/files/upload`（10MB 限制 + 类型白名单 + SHA256 命名）→ 返回 `{ data: { file_id, url } }`
- 访问：`/uploads/{file_id}` 静态服务（鉴权白名单，无需登录），后端 `server.go` 用 `http.Dir("uploads")` 提供
- 存值：`cover_image` 存上传返回的 URL（如 `/uploads/xxx.jpg`）
- 参考实现：`miniprogram/pages/enterprise/register.vue` 的 `uni.uploadFile` 已有先例

### 3. `price_fen`（价格）🟡

**现状**：`study_tours` 无价格列，`StudyTour` 模型无价格字段。前端按天数假定价（3天¥1280/2天¥880/1天¥480），误导用户。

**改动**（三处）：
1. **迁移**：新增 `000038_study_tours_price.up.sql`
   ```sql
   ALTER TABLE study_tours ADD COLUMN IF NOT EXISTS price_fen BIGINT DEFAULT 0;
   ```
2. **模型**：`internal/domain/models_batch1.go` 的 `StudyTour` 加
   ```go
   PriceFen int64 `json:"price_fen"`
   ```
3. **接口**：create/update handler 接收 `price_fen`，convStudy 输出它

> 参考：项目其他实体价格统一用 `price_fen`（分）命名，见 `drone_products`、`exhibitions`。

### 4. `schedule`（行程安排）🟡

**现状**：`study_tours` 无行程字段。前端按天数生成通用模板（"开营仪式/分组实操"），与真实行程不符。

**改动**：
1. **迁移**（000038 同文件追加）：
   ```sql
   ALTER TABLE study_tours ADD COLUMN IF NOT EXISTS schedule JSONB DEFAULT '[]';
   ```
2. **模型**：`StudyTour` 加
   ```go
   Schedule []StudySchedule `json:"schedule"`
   ```
   配套结构（如无现成类型则新建）：
   ```go
   type StudySchedule struct {
       Day   int      `json:"day"`
       Title string   `json:"title"`
       Items []string `json:"items"`
   }
   ```
3. **接口**：create/update 接收 `schedule`（JSONB 数组）

> **注意**：JSONB 写入要避免 nil slice 编码为 NULL（项目已知坑，见 `docs/数据设计/前端待补后端字段清单.md` 三）。用 `jsonbSlice` helper 归一化。

### 5. 报名管理端（可选）🟢

**现状**：研学报名的数据通过 `/api/submit` → `h5SubmitApplication` 存 `applications` 表（form_data JSONB 全量），管理端 `/api/admin/applications` 已能查询。**链路已通**，无需后端改动。
前端报名页若需接入管理端展示，属于前端工作。
